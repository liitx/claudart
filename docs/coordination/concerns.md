## C14. Precedence rule (owner, 2026-10-12): claudart and dartrix designs outrank outsourced dependencies
Outsourced = analyzer, `package:lints/recommended`, `dart format`, `mutation_test` defaults, any third-party lint.
Checked by running `dart analyze` in claudart (21 infos, all from `lints/recommended` or claudart's own added rules):
`prefer_const_constructors` 8, `prefer_function_declarations_over_variables` 2, `prefer_final_locals` 2,
`prefer_adjacent_string_concatenation` 2, `no_leading_underscores_for_local_identifiers` 2, `unnecessary_import` 1. [V]
- No analyzer rule contradicts a design rule today; these are style noise, not design clashes. Nothing overridden.
- Real clashes with outsourced tools: (a) `dart format` rewrites the hand-aligned grouped-arm style (never run whole-file);
  (b) `mutation_test -b` built-in string mutators survive `isNotEmpty` checks and produce equivalent-mutant noise.
- Precedence works the other way in zedup: its analysis_options downgrades two of OUR rules to `warning` (428 violations).
  Under this precedence those should return to `error` after the cleanup pass.
- dartrix has no custom_lint and only `lints/recommended`; the three rules it owns as law live in claudart.
- claudart's own `avoid_catches_without_on_clauses` is not third-party default and does not clash (typed catches are the
  design); `on Object catch (_)` only satisfies it nominally.
Mechanism if a real clash appears: disable the third-party rule in analysis_options with a comment citing the design rule.

## C15. Generated files are part of the design, so no rule may exempt them (owner, 2026-10-12)
Triage (claudart session, headless):
- Analyzer: NOT exempt. Probe in /tmp (four files with identical violations: plain, `*.g.dart` name, `// GENERATED - DO NOT EDIT`
  header, standard `// GENERATED CODE - DO NOT MODIFY BY HAND` header) gave identical `prefer_single_quotes`,
  `avoid_catches_without_on_clauses` and `unused_local_variable` hits in all four. [V]
- Repo tooling: no exclusion found. No `analyzer.exclude`, no `.g.dart` or `generated` skip in `tool/*.dart`,
  `tool/claudart_lints`, Makefile, `.githooks`, `.gitignore` or the mutation rules, in claudart, dartrix or zedup. [V by grep]
- What does exist: the `// GENERATED — DO NOT EDIT` header (3 generated files, 3 codegens) and CLAUDE.md's "no hand-edits
  below the generated marker". These are the drift guard that `stateOf` enforces by render-and-diff, not an exemption
  from lint or tests. Not removed: removing it would permit hand edits that the next `claudart link` silently reverts (#56).
- Real gap, in line with the owner's point: generated artifacts are not first-class in tests. `dependency_config.g.dart`
  is imported by nothing; the mutation tool pairs only `lib/x.dart` with `test/x_test.dart`, so a generated file and its
  renderer have no matrix cell; zedup's `UserConfigCodegen` always regenerates with no staleness check; zedup's three
  emitters have no callers. Proposed: every generated artifact gets (1) renderer test, (2) staleness state, (3) a dartrix cell.
